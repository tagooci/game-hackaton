# Локальный HTTPS для игры

Этот проект умеет работать в локальной сети по адресу:

```text
https://192.168.1.50:5179
```

HTTPS включается автоматически, если в `client/certs/` есть оба файла:

```text
client/certs/lan-cert.pem
client/certs/lan-key.pem
```

Если хотя бы одного файла нет, Vite запускается в прежнем режиме HTTP. Поэтому
сервер можно запускать обычными командами независимо от того, настроен ли
сертификат:

```sh
python -m uvicorn server.app:app --host 0.0.0.0 --port 8000
```

```sh
cd client
npm run dev
```

## Как это работает

Игроки подключаются к Vite по HTTPS:

```text
https://192.168.1.50:5179
```

Vite принимает защищённое соединение и проксирует запросы к FastAPI локально:

```text
HTTPS → Vite :5179 → HTTP → FastAPI :8000
WSS   → Vite :5179 → WS   → FastAPI :8000
```

Снаружи открывается только порт `5179`. WebSocket также защищён: страница,
открытая по HTTPS, подключается к нему через `wss://`. Отдельно менять код
клиента для переключения между `ws://` и `wss://` не нужно, потому что клиент
использует относительный путь `/ws`.

TLS устанавливается только при создании соединения. После этого WebSocket
остаётся постоянным, поэтому заметной прибавки к игровому ping ожидаться не
должно.

## Один раз: настройка компьютера-сервера

Эти действия выполняет только товарищ, на компьютере которого запущены
FastAPI и Vite. Ниже предполагается, что LAN-адрес этого компьютера —
`192.168.1.50`.

### 1. Установить mkcert

Установите `mkcert` подходящим способом для своей ОС. После установки команда
`mkcert` должна быть доступна в терминале.

### 2. Создать локальный центр сертификации

Выполните:

```sh
mkcert -install
```

Эта команда создаёт локальный корневой CA и добавляет его в доверенное
хранилище компьютера-сервера. Этот CA нужен, чтобы браузер доверял сертификату
игрового сервера.

### 3. Выпустить сертификат игрового сервера

Из корня проекта выполните:

```sh
mkdir -p client/certs
mkcert \
  -cert-file client/certs/lan-cert.pem \
  -key-file client/certs/lan-key.pem \
  192.168.1.50 localhost 127.0.0.1
```

Сертификат выпущен для IP `192.168.1.50`, поэтому игроки должны открывать
именно этот адрес. Если LAN-адрес изменится, сертификат нужно будет выпустить
заново с новым IP.

### 4. Передать команде только корневой сертификат

Узнайте папку, где mkcert хранит корневые файлы:

```sh
mkcert -CAROOT
```

Передайте остальным игрокам **только** файл:

```text
rootCA.pem
```

Передавать файл `rootCA-key.pem` нельзя: это закрытый ключ локального CA.
Файл `client/certs/lan-key.pem` также нельзя передавать или добавлять в Git.

### 5. Запуск

После появления обоих файлов сертификата запускайте проект как обычно:

```sh
python -m uvicorn server.app:app --host 0.0.0.0 --port 8000
```

```sh
cd client
npm run dev
```

Серверный компьютер может открыть тот же адрес:

```text
https://192.168.1.50:5179
```

## Один раз: настройка компьютеров остальных игроков

Каждому игроку нужен файл `rootCA.pem`, полученный от компьютера-сервера.
Игрок устанавливает этот файл как доверенный корневой сертификат на своей
операционной системе.

### macOS: компьютер-сервер

На Mac товарища, который запускает проект, достаточно выполнить:

```sh
mkcert -install
```

После создания сертификата из корня проекта:

```sh
mkcert \
  -cert-file client/certs/lan-cert.pem \
  -key-file client/certs/lan-key.pem \
  192.168.1.50 localhost 127.0.0.1
```

`mkcert -install` сам добавит корневой CA в связку ключей macOS. После этого
товарищ может открыть игру на этом же компьютере:

```text
https://192.168.1.50:5179
```

### macOS: компьютер игрока

Скопируйте на Mac игрока только файл `rootCA.pem`, затем установите его
в системную связку ключей:

```sh
sudo security add-trusted-cert \
  -d \
  -r trustRoot \
  -k /Library/Keychains/System.keychain \
  rootCA.pem
```

Или графически:

1. откройте `rootCA.pem` двойным щелчком;
2. выберите связку `System` или `login`;
3. добавьте сертификат;
4. в приложении «Связка ключей» откройте сертификат и выберите
   `Always Trust` для `Secure Sockets Layer (SSL)`.

После установки полностью закройте и снова откройте браузер.

### Windows: компьютеры остальных игроков

Откройте `rootCA.pem` двойным щелчком и выберите:

1. `Install Certificate`;
2. `Local Machine` или `Current User`;
3. `Place all certificates in the following store`;
4. `Trusted Root Certification Authorities`;
5. подтвердите установку.

После установки перезапустите браузер.

### Linux

Способ установки зависит от дистрибутива и браузера. Для системного хранилища
на Debian/Ubuntu обычно используется:

```sh
sudo cp rootCA.pem /usr/local/share/ca-certificates/game-hackaton.crt
sudo update-ca-certificates
```

После установки перезапустите браузер. Если браузер использует собственное
хранилище сертификатов, добавьте `rootCA.pem` в его хранилище доверенных CA.

## Подключение игроков

После установки `rootCA.pem` откройте:

```text
https://192.168.1.50:5179
```

Если браузер показывает предупреждение о сертификате, проверьте:

1. на компьютере установлен именно `rootCA.pem` от сервера;
2. в адресе используется `192.168.1.50`, а не другой IP;
3. системные дата и время установлены правильно;
4. на сервере присутствуют оба файла:
   `client/certs/lan-cert.pem` и `client/certs/lan-key.pem`;
5. Vite был перезапущен после создания сертификатов.

## Что хранить и что не коммитить

Можно хранить в проекте:

- `client/certs/.gitkeep`;
- этот файл с инструкцией.

Нельзя добавлять в Git или пересылать другим игрокам:

- `client/certs/lan-key.pem`;
- `rootCA-key.pem`.

Серверный `lan-cert.pem` не содержит закрытый ключ, но для простоты также
оставляйте папку `client/certs/` локальной и не коммитьте её содержимое.

## Возврат к HTTP

Если удалить или временно переименовать один из файлов:

```text
client/certs/lan-cert.pem
client/certs/lan-key.pem
```

Vite автоматически вернётся к HTTP-режиму. Тогда адрес будет:

```text
http://192.168.1.50:5179
```

Это резервный режим для случая, когда сертификат ещё не создан или временно
недоступен.
