# Проверка сценария по локальной сети

Теперь можно проходить сценарий вдвоём/втроём на разных ноутбуках.
Это отдельная тестовая комната с собственной серверной физикой, не `/ws/v2`.
В ней нет авторизации, большого мира и ресурсного менеджера команды.
Упрощённая проверка приоритета описана в `SCENARIO.md`.

## Ведущий: первоначальная установка

Открыть корень репозитория в терминале. Нужны Python 3.10+ и современный Node.js
(клиентские тесты проверены на Node 26).

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r server/requirements.txt
cd client
npm ci
cd ..
```

## Ведущий: запуск

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-scenario-lan.ps1
```

Скрипт собирает клиент и держит FastAPI в текущем терминале, порт 8011.
Останавливается через Ctrl+C. Дополнительный Vite для этого запуска не нужен.
Один worker обязателен, комната хранится в памяти одного процесса.

Без скрипта: `cd client; npm run build; cd ..`, затем:

```powershell
.\.venv\Scripts\python.exe -m uvicorn server.scenarios.lan:app --host 0.0.0.0 --port 8011 --workers 1 --ws-max-size 16384
```

Ведущий открывает `http://localhost:8011/?scenario-lan=1`.
Остальные — `http://<IPv4 ведущего>:8011/?scenario-lan=1`.
IPv4 Wi-Fi/Ethernet посмотреть через `ipconfig`, не брать адрес VPN/WSL.
Например: `http://192.168.1.10:8011/?scenario-lan=1`.
Все находятся в одной локальной сети; межклиентская изоляция Wi-Fi должна быть выключена.
При запросе Windows ведущий разрешает Python доступ в частной сети.
Проверка связи с другого ноутбука: `http://<IP>:8011/lab/health`.

## Прохождение

1. Каждый вводит имя и нажимает «Подключиться».
2. Каждый нажимает Enter или «Зайти в сценарий»; повторное нажатие снимает очередь.
3. После второго участника ждём 10 секунд третьего. Затем случайные роли,
   загрузка у всех и общий отсчёт 3 секунды.
4. W/S — тяга/задний ход, A/D — руль, Space — тормоз. Трамвай следует рельсам,
   руление ему не требуется. Управление применяется только после общего старта.
5. Для финиша нужно проехать перекрёсток и выехать всем кузовом за линию 30 м
   от центра по дороге. Отдельной графической финишной полосы пока нет.
6. На проезд 90 секунд. Итог и ошибки видны в панели. После результата через
   5 секунд возвращаемся в тестовое лобби; можно снова войти в очередь.

При разрыве соединения сценарий отменяется для всех. Клиент повторяет соединение
через 3 секунды, но не восстанавливает прежнюю сессию. Четвёртое соединение
отклоняется. Третий, подключившийся после старта пары, ждёт завершения в лобби.

Возврат на большой мир пока заменён тестовым лобби: сервер вычисляет и показывает
точку возврата, при успехе она соответствует выезду. Это не интеграция большой карты.
Результаты находятся в `scenario-lab.sqlite3` (Git игнорирует базу). Путь можно
переопределить переменной `SCENARIO_LAB_DB`.

## Разработка

Можно держать Python на 8011 и отдельно `cd client; npm run dev`.
Тогда страница на 5179, а Vite проксирует `/lab/ws` на 8011.
Адрес WebSocket берётся из хоста страницы, поэтому второму игроку не нужно
задавать localhost или переменную окружения.

## Изолированный тестовый протокол

Этот протокол относится **только** к `/lab/ws`, не изменяет командный v1/v2.

- `lab_join`: name; в течение 5 секунд. Ответ `lab_welcome`: playerId.
- `lab_queue`, `lab_leave_queue`: согласие на участие/отмена в лобби.
- `lab_ready`, `lab_load_failed`: sceneId; результат загрузки карты сценария.
- `lab_input`: sceneId, seq, throttle [-1,1], steering [-1,1], brake [0,1].
  Клиент отправляет 20 Гц; сервер применяет последний ввод на физике 30 Гц.
  Старый sceneId/seq, неконечные и выходящие за диапазон числа игнорируются.
  Через 250 мс без ввода сервер тормозит; на загрузке/отсчёте/финише ввод заблокирован.
- `lab_snapshot` каждые 50 мс: tick, playerId, sceneId, phase, players,
  queued, waiting, busy, countdown, remaining, result, returned.
  players — полный набор текущей тестовой сцены с ролью, позой, скоростью и finished.
  Фазы: lobby/loading/countdown/running/finished/cancelled.
- `lab_error`: text (например, комната заполнена), затем закрытие 1008.

Проверки: максимальный пакет 16 КиБ, не более 60 сообщений/с, максимум три
соединения. Этот сервер предназначен для локальной проверки команды.
