# Сценарий priority-01: первый этап

Ветка `feature/intersection-scenario`. Основа — v2 из `server/PROTOCOL.md`.

## Что реализовано

- `client/public/scenarios/priority-01.json`: общий источник размеров дороги,
  стоп-линий, ролей, стартов, финишного расстояния и таймеров для Python/Babylon.
- `server/scenarios/intersection.py`: независимая от FastAPI очередь и состояние
  экземпляра. Роли случайные, состав 2–3 человека. Второй запускает 10 секунд
  ожидания третьего; третий не сокращает этот срок. Дубли входа безопасны.
- Загрузка до 30 секунд, готовность всех, общий отсчёт 3 секунды, проезд 90 секунд.
  До running хост не должен применять управление. Ошибка загрузки/отключение
  отменяют задание, столкновение завершает его немедленно.
- Повернутые прямоугольные коллайдеры по габаритам ролей, промежуточные проверки
  движения между тиками. Финиш засчитывается только после входа в перекрёсток,
  пересечения финишной линии всем кузовом и направления машины наружу.
- `server/scenarios/results.py`: SQLite с уникальным resultId, повтор не дублирует запись.
- `client/src/scenarios/junctionScene.ts`: low-poly карта и заменяемые модели.
  Корень каждой модели находится в центре основания на Y=0, вперёд = +Z.
- `client/src/scenarios/transition.ts`: адаптер загрузки с отменой старого запроса,
  освобождением старой сцены, scene_ready/scene_failed, защитой epoch и startTick.
- Отдельный offline-просмотр карты с тестовым управлением, не подменяющий v1.

## Просмотр карты

Из `client/`:

```powershell
npm ci
npm run dev
```

Открыть `http://localhost:5179/?scenario-preview=1`. В меню можно выбрать любой
из трёх транспортов. W/S — тяга/задний ход, A/D — руление автомобилей,
Space — тормоз. Это только просмотр ресурсов: сеть, приоритет и результаты
в этом режиме не работают. Тестовое управление не предназначено для общего мира.

## Контроль правил: ограничения прототипа

На входе кузова в центральную область сохраняются ещё не завершившие проезд
участники. После выезда определяется фактический манёвр и фиксируется нарушение
порядка: трамвай, участник справа, встречный при левом повороте.
Нарушение не прерывает задание. Итог успешен, если все выехали и ошибок нет.

Это **консервативная учебная проверка порядка въезда**, пока не полная модель ПДД:
не различаются все непересекающиеся траектории, расстояние до приближающегося
участника и факт вынужденного изменения его скорости. Возможны лишние нарушения
на непересекающихся маршрутах. Перед учебной приёмкой нужны конфликтные маршруты
из карты и тесты манёвров; текущую проверку нельзя выдавать за окончательную оценку.
Выезд по газону/встречной полосе также требует отдельной проверки правил.

## Подключение к работе других участников

Этот коммит не добавляет `/ws/v2`, вход/аккаунты, физику или большой мир.
Существующие `server/app.py`, v1-сообщения и сетевой клиент остаются рабочими.
Модули сценария пока не вызываются сетевым сервером. Мультиплеерный сценарий
целиком ещё не интегрирован.

Хост v2 должен:

1. Проверять серверную зону и согласие Enter; вызывать `queue.join` с ID аккаунта
   и `ReturnPoints`: исходная безопасная точка, четыре точки выезда и исходный
   тип машины. При выходе из зоны/отключении снимать из очереди.
2. На тике вызывать `queue.advance(monotonic_time)`. Один игрок может находиться
   только в одной очереди/сессии; это обеспечивает реестр хоста.
3. На создании сессии блокировать ввод, назначать новый sceneId/epoch и применять
   spawn/габариты роли. Отправлять scene_prepare с ролями и HTTP-планом контента.
4. Проверять sceneId/epoch/revision scene_ready в сетевом слое; после этого
   вызывать `mark_ready`. Превратить общий `start_at` в один startTick для всех.
5. Считать движение на Python и передавать в `advance` только авторитетные Pose
   по фиксированному тику. Не передавать сюда v1 state из браузера.
6. Блокировать движение до старта/после результата. Передавать нарушения в rule_event
   и результат через scenario_result, сопоставляя доменные поля формату v2.
7. Один раз сохранить результат в ResultStore. Через resultSeconds=5 вернуть
   участников посредством нового scene_prepare общего мира. `return_pose`
   выбирает соответствующий выезд только при общем успехе; иначе — origin.
   Восстановить исходный vehicle_type и обнулить скорость.
8. На клиенте использовать transition-адаптер с менеджером ресурсов команды.
   Preview-loader не учитывает ресурсный бюджет v2 и не заменяет его.

Обновление этапа, которое нужно согласовать с владельцем общего контракта:

| v2 в main | Уточнение пользовательского ТЗ для нашей ветки |
| --- | --- |
| Два участника, третий ждёт | 2–3, третий получает tram_driver / tram |
| Автовход после остановки в зоне | Подтверждение Enter, сервер проверяет допустимость |
| Отсчёт 2 секунды | 3 секунды |
| Возврат к сохранённой точке | При успехе — точка фактического выезда |

Имена новых сетевых сообщений самостоятельно не вводятся: согласие Enter и
новые типы транспорта должен оформить владелец `server/PROTOCOL.md` до сетевой
интеграции. Внутренние Python-события не являются новым WebSocket-контрактом.

## Проверки

```powershell
python -m unittest server.tests.test_intersection -v
cd client
npm test
npm run build
```

Проверены очередь/выход из неё, две и три роли, готовность, устаревшая сцена,
тайм-аут, столкновение, порядок проезда, возврат, повторная запись результата,
поздняя загрузка карты, блокировка управления и освобождение Babylon-сцены.
