# Карта в игровом клиенте

Текущая карта импортирована из `blender/compact-reference.blend` и
`blender/compact-reference.graph.json`, модели — локальный Kenney City Kit Roads.
111 дорожных модулей, круговой перекрёсток, пешеходные переходы, многоуровневые
проезды, опоры, 74 фонаря и дорожные знаки. Геометрия, масштабы и преобразования
экземпляров берутся из Blender. JSON портов используется для проверки стыков
и связности; уровни моста остаются отдельными вершинами графа.
В игровом пространстве Blender XYZ преобразуются в (-X, Z, -Y).
Высота и наклон автомобиля вычисляются Python-сервером по треугольникам
дорожного покрытия, поэтому учитываются криволинейные подъёмы и спуски.

Вход и управление остаются игровыми: HTTP-авторизация, `/ws/v2`, Python-физика.
В scene_prepare сервер передаёт `plan.mapManifestUrl`. Клиент ждёт загрузки
первой области до scene_ready, затем обновляет область по положению машины.
Подгрузка идёт в фоне: старая дорога остаётся видимой, общие meshes сохраняются.
Новые шейдеры готовятся заранее; матрицы объектов переключаются одним шагом.
Участки имеют размер 20 м. Полный круг загрузки — 80 м вокруг машины,
план пересчитывается каждые 2,5 м. До запроса освобождаются только участки
за этим кругом. Туман от 40 до 60 м и камеры не более 12 м скрывают границу.
Ближние участки не пропускаются ради экономии бюджета: при нехватке выдаётся ошибка.
Старые ресурсы освобождаются после переключения, а бюджет включает одновременно
старые, подготовленные и ещё загружаемые файлы. Обычная подгрузка не включает тормоз.
При ошибке текущая дорога сохраняется и показывается сообщение. После выхода загрузчик
освобождает модели, включая запросы, завершившиеся после удаления сцены.

Начальная позиция берётся из spawn манифеста. Сохранённая позиция переносится
на старт только при смене worldId. Python вычисляет высоту и наклон по дорожным
поверхностям из navigation.json. В БД сохраняются координаты, уровень и worldId:
после переподключения машина на мосту не попадает на проезд под ним.

## Ограничения

Загрузчик считает уникальные опубликованные байты ресурсов мира. Бюджет —
`floor(manifest.worldBytes / 10)`. В worldBytes входят ресурсы из манифеста,
`residentResources` (единая машина со встроенной палитрой) и сам манифест.
Постоянные ресурсы резервируются на весь сеанс и показаны в `window.roadCache`.
При каждом запросе проверяется `activeBytes + reservedBytes <= budgetBytes`;
если места нет, файл не запрашивается. Размер и SHA-256 чанков/моделей карты
проверяются до загрузки в Babylon. У `/content/` и `/assets/` стоит no-store.
Это лимит файлов игрового контента; распакованные меши, текстуры GPU, карта теней,
JavaScript и служебные сетевые сообщения не являются измерением этих байтов.
Их RAM/VRAM нельзя приравнивать размеру GLB.

Сервер проверяет столкновения ориентированными боксами объектов и автомобилей.
Боксы бордюров подняты на 2,5 м без изменения видимых моделей; проёмы стыков
остаются открытыми. Движение разбивается на подшаги до 20 см, чтобы кузов
не проходил сквозь тонкие препятствия. Проверка высот сохраняет проезд под мостом.
Опора учитывает переднюю и заднюю оси, в воздухе действует гравитация.
Нет проверки ПДД, работающих фаз светофоров и серверного запрета выезда за загруженную область. Планы участков выбирает
клиент; полноценное управление контентом сервером остаётся отдельным этапом.

Авторский интерфейс предпросмотра и его управление камерой в игру не перенесены.
## Повторный импорт из Blender

Готовые ресурсы уже находятся в `client/public/content/` и не требуют Blender при игре.
Для обновления карты остановите Python-сервер, сохраните Blender-файл и выполните:

```sh
cd /path/to/game-hackaton
.venv/bin/python -m pip install -r client/scripts/requirements-assets.txt
.venv/bin/python client/scripts/import-blender-map.py \
  --scene blender/compact-reference.blend \
  --environment-scene blender/compact-city.blend \
  --assets "/path/to/downloads/kenney_city-kit-roads/Models/GLB format" \
  --blender /Applications/Blender.app/Contents/MacOS/Blender
npm --prefix client run build
.venv/bin/python -m uvicorn server.app:app --host 0.0.0.0 --port 8000
```

Экспортер запускает отдельный Blender в фоне и не меняет исходный .blend.
Поверхности, нижние грани перекрытий, боксы, граф, чанки, размеры и SHA-256 создаются автоматически. После импорта
обновите страницу. При изменении дорожного графа worldId меняется, старые позиции
переносятся на spawn. В рамках текущего импорта сохранённые позиции существующих
игроков отдельно расставлены по прямым наземным участкам.

GLB и JSON чанков хранятся в gzip-контейнерах с расширением `.bin`, чтобы Vite
не распаковывал их автоматически до проверки SHA-256. Manifest помечает их
`encoding: gzip`; загрузчик проверяет опубликованные байты и распаковывает их
встроенным DecompressionStream. Текстуры Kenney перенесены в цвета вершин,
внешние файлы и CDN для моделей не требуются. Бюджет по-прежнему считает размеры
опубликованных файлов; это не измерение распакованной RAM/VRAM.
Серверный navigation.json содержит точную геометрию поверхностей и в клиент
не загружается. Его размер входит в данные мира. Модель игровой машины со
встроенной текстурой входит в общий бюджет и хранится как `sedan.glb.bin`.

## Граница текущего учёта

Текущий небольшой мир: около 4,17 МБ, из них 3,76 МБ — серверный navigation.json.
Полный набор визуальных ресурсов вместе с машиной и манифестом — около 406 КБ.
В центре радиус 80 м охватывает почти всю карту: клиент может держать весь этот
набор при бюджете 417 КБ. Следовательно, текущий счётчик ограничивает 10% всех
ресурсов мира, включая серверную геометрию, а не 10% только визуального контента.

## Проверка загрузки и кэша

В режиме разработки (порт 5179), после входа в игру:

1. Откройте DevTools → Network, включите Preserve log и фильтр `/content/`.
   Начальная загрузка покажет manifest.json, overview.json, JSON участков и упакованные GLB (`.bin`).
   Машина загружается отдельно по `/assets/car-kit/sedan.glb.bin` и тоже входит в счётчик.
   При езде появляются запросы только недостающих ресурсов. У ответов no-store.
2. В Console выполните `window.roadCache` или
   `console.table(window.roadCache.resources)`. Это снимок внутреннего кэша
   приложения: IDs и размеры находящихся сейчас в памяти файлов.
3. Для наблюдения во время езды:

```js
window.cacheWatch = setInterval(() => {
  const c = window.roadCache;
  if (!c) return;
  console.log({
    chunk: c.chunk, next: c.requestedChunk,
    used: c.activeBytes, reserved: c.reservedBytes, budget: c.budgetBytes,
    fits: c.activeBytes + c.reservedBytes <= c.budgetBytes
  });
}, 1000);
```

Остановка: `clearInterval(window.cacheWatch)`.
Поле chunk показывает ячейку плана с шагом 2,5 м; IDs файлов перечислены в resources.
При переходе reservedBytes временно увеличивается, chunk меняется после готовности.
После проезда ненужные IDs исчезают из resources. Значение fits должно быть true.
Network хранит историю запросов: её суммарный объём не равен текущему кэшу.
В Application → Cache Storage эти данные не появятся: это кэш приложения в памяти,
а не постоянный браузерный кэш. Счётчик показывает размеры файлов, не расход RAM/VRAM.
